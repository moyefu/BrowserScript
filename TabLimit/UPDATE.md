# 更新日志 (Changelog)

本项目遵循 [Semantic Versioning](https://semver.org/lang/zh-CN/) 语义化版本规范。

---

## [0.5.1] - 2026-09-18

### 🐛 修复高并发批量开标签场景下的漏关与误提示问题
- **修复批量关闭指令覆写踩踏（解决测试1漏关残留）**：
  - 此前多标签超限时在 `for` 循环中连续发送单条 KILL 广播，高频写入导致 GM 存储相互覆盖、消息丢失；
  - 现改为单次批量下发 `targetTabIds: [...]` 数组，所有超额目标标签一次性全量接收并关闭，彻底根除漏关与残留问题。
- **升级为三重通信总线（引入 unsafeWindow 原生页面上下文）**：
  - 借助 `unsafeWindow` 穿透扩展沙箱限制，直接使用原生 `BroadcastChannel` 与 `localStorage` 的 `storage` 事件；
  - 结合 GM 跨域监听形成三重立体通信通道，同源跨标签通信零延迟、不丢包。
- **修复异步关闭过早触发提示屏的误报问题**：
  - 浏览器多标签并发 `window.close()` 具有异步 IPC 耗时，此前 80ms 检查过于敏感，在窗口销毁过程中误判为关闭失败并弹出拦截屏；
  - 将缓冲检测时长放宽至 1200ms，正常关闭的标签在 100~300ms 内销毁，绝不会再误现拦截提示屏；仅在真正受安全限制阻拦的根标签上才展示提示。

## [0.5.0] - 2026-09-18

### 🚀 架构重大重构（彻底解决多关、少关问题）
- **Ping-Pong 实时探活机制**：
  - 弃用容易因浏览器崩溃/杀进程残留的静态共享存储列表与 GM 锁；
  - 标签打开时广播探活（`PING`），存活标签响应（`PONG`），无响应或已死亡标签自动排除，**彻底根除幽灵标签积累导致的误杀（关多）**。
- **双通道广播与精准定向关闭**：
  - 引入原生 `BroadcastChannel`（同源微秒级延迟）结合 `GM_addValueChangeListener`（跨子域/跨域通配），打破后台标签定时器休眠限制；
  - 新标签打开汇总后精准向超额目标标签发送 `KILL` 指令，超额旧标签即时唤醒并极速关闭，**彻底根除休眠导致的漏关/迟关（关少）**。
- **标签年龄固化（sessionStorage）**：
  - 通过 `sessionStorage` 记录标签 `tabId` 与原始创建时间戳，页面刷新（F5）或同标签内点击跳转不再重置标签年龄，避免误关。
- **0~100ms 极速响应**：
  - 判定超限后立即关闭，显著降低页面资源加载消耗与视觉闪烁。
- **优雅拦截提示屏**：
  - 当浏览器因安全策略限制禁止 `window.close()` 时，自动停止加载并展示现代化深色拦截提示屏，并永久退出探活通道。
- **配置与可见性热重载**：
  - 监听 `Config.tab_limit_list` 动态变更自动重新评估；支持页面可见性恢复（`visibilitychange`）时的快速复核。

## [0.4.0] - 2026-09-17

### 🐛 修复标签不关闭问题
- 修复空锁记录仍被当作有效锁占用的问题，锁释放后写入空字符串；
- 上锁判断改为只认非空 `lockId`，避免旧锁残留导致后续标签无法写登记表；
- 修复“当前标签已被清理却视为保留”的逻辑，现在只有仍登记且属于保留集合才保留。

### 🔒 调整为锁 ID 串行化流程
- 锁值改为唯一 `lockId` + 时间戳；
- 获取锁后读取登记表到本地变量并修改；
- 写回前再次校验锁 ID，不一致则放弃本次修改并循环等待锁释放；
- 所有模式保留低频兜底轮询，通过 `changeCount` 感知其他标签写入，降低漏关概率。

## [0.3.0] - 2026-09-17

### ✨ 新增 GM 租约锁
- 登记表读写前获取 `tabLimit.<规则通配符>.lock`，避免多个标签同时运行 JS 时把列表写坏；
- 锁不是当前标签持有时不修改登记表，按 100ms 间隔等待重试；
- 锁带 3 秒租约，过期后允许其他标签接管，防止标签异常退出导致死锁；
- 登记、`shouldClose` 判断、`pagehide` / `beforeunload` 清理均在锁内重新读取最新登记表。

## [0.2.0] - 2026-09-17

### ✨ 按模式分流监听策略
- **new 模式**：新标签打开时当前标签会从"保留"变为"应关闭"，必须 `setInterval` 持续监听（每 2s 一次）；
- **old 模式**：保留旧标签意味着当前标签越旧越安全，新标签不会把它挤出保留集合，**打开时一次性判定即可，无需轮询**；
- 判定应关闭 → 立即 `setTimeout` 300ms 关闭；判定保留 → new 模式启动轮询，old 模式静默等待用户手动关闭。

### 🧹 清理逻辑优化
- 关闭前先把当前标签从登记表移除（best-effort，避免堆积）；
- `closeSelf()` 后 `clearInterval(ticker)` 停止监听（仅 new 模式有 ticker）；
- 用 `pagehide` 优先清理，`beforeunload` 兜底（SPA / bfcache 场景更可靠）。

## [0.1.0] - 2026-09-17

### 🎉 初始版本发布

- **核心标签登记与自动关闭**：
  - 支持从用户配置中读取 `URL 通配符 上限数 new/old` 多行规则；
  - 每个 URL 维护独立的标签登记表（时间戳 + 唯一 ID）；
  - `new` 模式保留最新 N 个标签，`old` 模式保留最旧 N 个标签；
  - 超出上限的标签延迟 300ms 自动 `window.close()`。

- **拦截兜底与用户体验提升**：
  - 捕获浏览器安全限制异常（非脚本打开的标签无法 `window.close()`）；
  - 新增全屏降级拦截提示，确保未授权关闭时依然能有效提示用户。

- **数据自清理**：
  - 当前标签被关闭时自动从登记表移除；
  - 标签刷新或手动关闭时通过 `beforeunload` 兜底清理登记表。
